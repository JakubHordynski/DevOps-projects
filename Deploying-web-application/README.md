# Web Deploy — Production Web Application Deployment Template

Turn any standard Node.js, Astro, React, or Vue web application into a highly optimized, production-ready container stack. Web Deploy is a universal infrastructure template and step-by-step guide designed for developers who have built a web application and want to deploy it cleanly using Docker, Nginx, local HTTPS via Traefik, and real-time monitoring with Prometheus, Loki, and Grafana.

Instead of running a heavy development server in production, this boilerplate walks you through using multi-stage Docker builds to compile your code and serve only the static files—shrinking the final container image down by ~90% compared to standard single-stage Node.js containers.

Web Deploy keeps things focused on what you actually need to take a website live: automated build compilation, reverse proxy SSL termination, and a complete observability and alerting stack out of the box.

## Features
- Universal multi-stage Docker build (compiles Node.js/Astro/React/Vue apps and serves them via lightweight Nginx)
- Minimal production container footprint (`nginx:alpine` runtime with Gzip compression enabled)
- Automated Reverse Proxy and custom domain routing via Traefik v3.0
- Local HTTPS/SSL certificate integration using mkcert
- Full observability stack: metrics scraping (Prometheus), alerting (Alertmanager), and log aggregation (Loki)
- Pre-configured visual dashboards and automated data sources (Grafana)
- Instant downtime notifications via Discord Webhooks

## Requirements
- Docker & Docker Desktop
- Docker Compose
- Node.js (v18+ or LTS recommended if testing builds locally)
- mkcert (for generating trusted local SSL certificates)
- Git

## Step-by-Step Deployment Guide

Follow these steps to containerize and deploy your own web application using this template.

### 1. Clone the template and add your application code
Clone this repository to your local machine and navigate to the deployment folder:

    git clone https://github.com/JakubHordynski/DevOps_projects.git
    cd DevOps_projects/Deploying-web-application

Where to place your website files:
Copy your web application's source files (`package.json`, `package-lock.json`, `src/`, `public/`, and framework config files like `astro.config.mjs` or `vite.config.js`) directly into the `Deploying-web-application/` directory alongside the `Dockerfile`.

    Deploying-web-application/
    ├── Domain_with_https/
    ├── nginx/
    ├── public/               <-- Your static assets here
    ├── src/                  <-- Your application source code here
    ├── package.json          <-- Your dependencies and build script here
    ├── package-lock.json
    └── Dockerfile

Ensure your `package.json` contains a `build` script (`"build": "..."`) that outputs compiled static files into a `dist` folder (default for Astro, Vite, and Vue).

### 2. Build the optimized Docker image
The included `Dockerfile` uses a two-stage process: first, it installs dependencies and compiles your site using a Node LTS image; second, it copies only the compiled `dist/` directory into a minimal `nginx:alpine` image:

    FROM node:lts AS build
    WORKDIR /app
    COPY package*.json ./
    RUN npm install
    COPY . .
    RUN npm run build

    FROM nginx:alpine AS runtime
    COPY ./nginx/nginx.conf /etc/nginx/nginx.conf
    COPY --from=build /app/dist /usr/share/nginx/html
    EXPOSE 8080

Note: If your framework compiles files into a folder named `build/` (e.g., Create React App) or `out/` (Next.js static export) instead of `dist/`, change `/app/dist` in the `COPY --from=build` line to match your framework's output folder.

Build your production container image (using the `web-app:1.0` tag so it matches the service definition in `Domain_with_https/docker-compose.yml`):

    docker build -t web-app:1.0 .

### 3. Generate local SSL certificates (HTTPS)
To serve your application over `https://` locally without browser security errors, generate certificates using `mkcert` inside `Domain_with_https/certs/` matching the filenames configured in `Domain_with_https/traefik/dynamic.yml`:

    mkdir -p Domain_with_https/certs
    mkcert -install
    mkcert -cert-file Domain_with_https/certs/myapp.local+2.pem -key-file Domain_with_https/certs/myapp.local+2-key.pem "myapp.local" "dashboard.local" "api.local"

### 4. Configure your custom local domain
Map the local domains defined in `Domain_with_https/traefik/services.yml` (`myapp.local`, `dashboard.local`, `api.local`) to your local loopback IP address so your browser knows where to route the traffic:
- On Windows, open Notepad as Administrator and edit: `C:\Windows\System32\drivers\etc\hosts`
- On Linux/macOS, edit: `/etc/hosts`

Add the following lines at the bottom of the file and save it:

    127.0.0.1 myapp.local
    127.0.0.1 dashboard.local
    127.0.0.1 api.local

(Optional) To use your own custom domain name instead of `myapp.local`, update `Host("myapp.local")` inside `Domain_with_https/traefik/services.yml` and regenerate the certificate in Step 3.

### 5. Launch the entire infrastructure stack
Move into the orchestration directory and start Traefik, your web application, Prometheus, Alertmanager, Loki, and Grafana in detached mode:

    cd Domain_with_https
    docker compose up -d

Verify that all containers are up and running:

    docker ps

## Accessing Your Services

Once the stack is running, open your web browser to interact with your infrastructure:

  https://myapp.local
- Grafana Monitoring & Dashboards:
  http://localhost:3000
- Prometheus Metrics UI:
  http://localhost:9000
- Traefik Internal Metrics Endpoint:
  http://localhost:8899/metrics

## Configuring Real-Time Discord Alerts

To receive instant notifications on Discord whenever your web server or reverse proxy goes offline:
1. Create a private Discord server (or channel), go to Channel Settings -> Integrations -> Webhooks, create a New Webhook, and copy the Webhook URL.
2. Open Grafana at http://localhost:3000 and navigate to Alerting -> Contact points.
3. Create a new contact point, select Discord as the integration type, and paste your Webhook URL.
4. Navigate to Alerting -> Alert rules and create a new rule targeting your Prometheus data source.
5. Set the query to monitor the Traefik instance (`up{job="traefik"}`) and set the threshold condition to `IS BELOW 1`.
6. Save the rule. Whenever the container stops or becomes unreachable, Grafana will fire a `[FIRING]` alert to Discord and send a `[RESOLVED]` notification once the service recovers.

## Security Best Practices
- Never upload private SSL keys or certificates (`*.pem`, `*.key`) from `Domain_with_https/certs/` to a public Git repository. Keep the certificate files listed in `.gitignore`.
- Do not expose port `9000` (Prometheus) or port `3000` (Grafana) directly to the public Internet without placing them behind a reverse proxy with authentication or a VPN.
- Change the default Grafana administrator login credentials immediately after starting the stack for the first time.
- When moving from local testing to a public VPS/cloud server, replace `mkcert` with Traefik's built-in Let's Encrypt ACME certificate resolver.

## Troubleshooting & Debug

### 1. Application does not load in browser (502 Bad Gateway / Connection Refused)
By default, the custom `nginx/nginx.conf` is configured to listen on port `8080` rather than port `80`. If Traefik cannot reach your application container, check two things:
- Ensure `EXPOSE 8080` is present in your `Dockerfile` and `listen 8080;` is set inside `nginx/nginx.conf`.
- Open `Domain_with_https/traefik/services.yml` and verify that the loadBalancer URL forwards traffic to `http://web-app:8080`.

### 2. Grafana or Prometheus cannot reach Traefik metrics
All services in `Domain_with_https/docker-compose.yml` must share the same Docker bridge network (`public`). If Prometheus shows the target as `DOWN`, inspect `docker-compose.yml` and ensure that `traefik`, `prometheus`, `grafana`, `loki`, `alertmanager`, and `web-app` are all attached to the `public` network.

### 3. Docker image size is still over 1 GB
If your compiled image is unexpectedly large, verify two things:
- Ensure the `.dockerignore` file is present in the root directory so local `node_modules/` and `.git/` folders are not copied into the build context.
- Confirm that your `Dockerfile` uses `FROM nginx:alpine AS runtime` for the final stage so the heavy Node.js build layer is discarded after compilation (typically reducing final image size by ~90%).
